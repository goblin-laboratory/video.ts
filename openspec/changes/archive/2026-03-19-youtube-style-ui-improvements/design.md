## Context

当前播放器有两个独立的控制栏组件：`LivePlayerBar`（直播）和 `PlaybackPlayerBar`（回放），它们各自实现了音量控制逻辑，存在代码重复。UI 样式与 YouTube 风格存在差异，包括进度条圆点颜色、中心播放按钮样式、自动隐藏行为等。演示使用的播放地址也需要更新为实际可用的 FLV 和 HLS 地址。

## Goals / Non-Goals

**Goals:**
- 统一直播和回放的音量控制组件，减少代码重复
- 采用 YouTube 风格的 UI 配色和样式
- 优化暂停时的用户体验，保持控制栏可见
- 修正图标使用和按钮尺寸一致性
- 更新演示播放地址

**Non-Goals:**
- 不修改内核播放逻辑
- 不重构整体架构，仅优化 UI 层
- 不添加新的功能控件

## Decisions

### 1. 音量控制组件提取
**决定**: 创建共享的 `VolumeControl` 组件，包含静音按钮和音量滑块
**替代方案**: 继续在两个控制栏中重复实现
**理由**: 减少代码重复，确保行为一致，便于后续维护

### 2. YouTube 风格样式
**决定**: 采用 YouTube 的红色 (#FF0000) 主题，白色圆点，半透明文本阴影
**替代方案**: 保持当前配色或自定义其他主题
**理由**: YouTube 是行业标准，用户熟悉其交互体验

### 3. 暂停时控制栏保持可见
**决定**: 修改 `AutoHide` 逻辑，暂停时强制显示控制栏且不自动隐藏
**替代方案**: 完全移除自动隐藏功能
**理由**: 暂停时用户通常需要进行操作，保持控制栏可见提升可用性

### 4. 中心播放按钮样式
**决定**: 移除圆形半透明背景，改用纯播放图标 + 半透明文本阴影
**替代方案**: 保持当前圆环样式或使用其他形状
**理由**: 更接近 YouTube 风格，更简洁现代

### 5. 按钮尺寸统一
**决定**: 音量按钮使用与全屏按钮相同的 `TooltipButton` 组件，确保尺寸一致
**替代方案**: 单独调整音量按钮样式
**理由**: 统一交互体验，减少样式碎片化

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 修改自动隐藏逻辑可能影响现有用户习惯 | 中 | 仅在暂停时改变行为，播放时保持原有逻辑 |
| 样式变更可能与现有应用主题冲突 | 低 | 样式限定在播放器组件内，不影响外部 |
